>> I don't believe Echolot checks key expiry dates.  It sends remailer-key

>> > What happens between the time that a key expires and the pinger

>> This is getting into the realms of why stats plummet every key rotation.
>> Echolot recognizes remailers by keyid so there can be more than one
>> keyid associated with any given remailer name/address.
>>
>> If more than one keyid is associated with a remailer, the stats results
>> are a combination of all the keyids pinged.  If one keyid returns 100%
>> and the other 0%, the stats will drop to 50%.  This is exactly what
>> happens at rotation time.
>>
>> Just before key rotation, Echolot gets a response from a remailer-key
>> request showing the key that's about to expire.  From that time, it will
>> ping that key for (default) 5 days even though the remailer never
>> advertises it again.  Echolot *thinks* its pinging that key, but
>> Mixmaster doesn't actually send its pings due to the expired key.
>> Echolot's results for that key drop to 0%.  Meanwhile the remailer has
>> generated and advertised a new keyid.  Echolot picks this up and pings
>> that key too.  Hopefully getting 100% returns.  For 5 days, Echolot
>> pings both keys, getting 0% from one and 100% from the other, making 50%
>> uptime.  After 5 days, the expired key is considered dead.  Echolot
>> recalculates its stats based on just the remaining keyid and uptime
>> stats return to 100%.
>
> That really seems like an inefficient process. Isn't there any way 
> to get the pingers to do it differently, so that the 5 days of 
> really bad stats that don't reflect reality don't happen anymore?

- From the pingd.conf manpage:-

expire_keys [seconds]
    After how long to expire received keys if they were not
    updated by remailer-key replies.

        Default: 'expire_keys' =>  5*24*60*60, # 5 days
        Example: 'expire_keys' =>  7*24*60*60, # 1 week

Changing this to a lower value would reduce the impact of key rollover.
It doesn't explain what happens though as the remailer should honour the
expired key long after it stops advertising it.
